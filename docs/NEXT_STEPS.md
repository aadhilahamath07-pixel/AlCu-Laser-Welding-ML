# Research project: next-step checklist

**Updated:** 16 November 2026  
**Repository:** [AlCu-Laser-Welding-ML](https://github.com/aadhilahamath07-pixel/AlCu-Laser-Welding-ML)

This checklist distinguishes completed analysis from files that are not yet archived in GitHub. Do not mark a data-archiving task complete until the actual file is present in the repository and its provenance has been checked.

## A. Archive the existing work

- [ ] Obtain the final 84-record master_experimental_dataset.csv generated by Notebook 05.
- [ ] Obtain the Notebook 06 audited master CSV, audit report and data dictionary.
- [ ] Obtain the standardised conventional and wobble CSVs generated by Notebooks 03 and 04.
- [ ] Verify each generated file against the original source files and the notebook version used.
- [ ] Review redistribution/licensing terms for each extracted dataset.
- [ ] Commit approved CSVs to data/processed/ and data/master/; retain raw source files unchanged.
- [ ] Archive Notebook 08 and Notebook 09 fold metrics, pooled metrics, out-of-fold predictions and plots under a clearly versioned results/ directory.
- [ ] Record data-file versions/checksums and the notebook commit used to generate each result.

## B. Resolve existing data-quality questions

- [ ] Check the six conventional all-zero geometry records against the original source. Preserve the original values and document the interpretation; do not silently delete or recode them.
- [ ] Recheck the seven missing wobble bead-width measurements: six marked “Specimen cut” and one unexplained.
- [ ] Verify the four flagged Lee et al. (2022) force records against the original publication. Keep their force-target eligibility disabled unless resolved.
- [ ] Record exact DOI, source title, authors, table/figure/page, units and extraction notes for every source group.

## C. Expand and harmonise the evidence base

- [ ] Search for additional experimental Al–Cu laser-welding studies with extractable numerical process/quality data.
- [ ] Screen each candidate study for material grades, thicknesses, joint configuration, laser type/mode, process parameters and measurement definitions.
- [ ] Keep conventional and wobble datasets separate unless comparability is demonstrated.
- [ ] Add only measured values supported by the source; preserve missingness and replicate identity.
- [ ] Maintain a source-level literature register and a record-level provenance trail.

## D. Strengthen modelling and validation

- [ ] Reassess target eligibility after data expansion.
- [ ] Establish simple baselines before testing more complex models.
- [ ] Keep repeated specimens/process conditions grouped during validation.
- [ ] Use study-level external validation only when enough independent studies are available; otherwise state the limitation clearly.
- [ ] Report MAE, RMSE, R², sample counts, independent group counts and uncertainty.
- [ ] Keep all preprocessing inside the training folds.
- [ ] Do not claim causal effects, an optimum welding window or production readiness from the current preliminary results.

## E. Prepare the paper

- [ ] Finalise research questions and scope after the data expansion decision.
- [ ] Write the literature review and explain the Al–Cu joining challenges using cited primary sources.
- [ ] Document dataset selection, extraction, cleaning, provenance and exclusions.
- [ ] Present EDA and source-specific ML results with fold stability and limitations.
- [ ] Discuss physical interpretation without treating correlations or feature importance as causation.
- [ ] Prepare figures, tables, references, conclusions and limitations.
- [ ] Select a suitable journal and format the manuscript to its author guidelines.

## Current decision

The current best preliminary target is conventional weld bead width (21 records, seven process-condition groups; Extra Trees pooled out-of-fold MAE 0.0984 mm, RMSE 0.1372 mm, R² 0.7487). This result is not externally validated and fold-level R² is unstable. Wobble face bead width remains exploratory (29 records, 17 groups). The next immediate priority is to archive the actual generated datasets and outputs, then resolve source-quality questions and expand comparable experimental evidence—not to claim a final predictive model.
